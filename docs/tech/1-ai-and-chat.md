# Искусственный интеллект и Чат-Агент (AI & Chat)

Взаимодействие с ИИ выстроено по гибкой схеме и поддерживает два режима работы в зависимости от конфигурации:
1. **Выделенный микросервис (`backend`):** Fastify-сервер на Node.js, обрабатывающий запросы `/analyze` и `/chat` напрямую.
2. **Серверлесс-архитектура:** Next.js API Routes (`/api/ai/analyze`, `/api/ai/chat`) вызывают бессерверные функции **Supabase Edge Functions** (`analyze-note`, `embed`).

Оба пути используют одинаковые промпты, работают с моделями через провайдера **OpenRouter** и обращаются к базе **Supabase** (PostgreSQL + pgvector) для RAG и сохранения эмбеддингов.

---

## 1. Автоматический анализ заметок (`/analyze`)

Когда пользователь создает или редактирует заметку, клиент отправляет запрос к `/analyze`. Этот процесс асинхронный и происходит в фоне.

### Как работает пайплайн:
1. **Проверка хэша:** Текст заметки нормализуется, и от него вычисляется хэш `computeHashNode(normalized)`. Если хэш совпадает со старым (`metadata.content_hash`), анализ прерывается (экономия токенов).
2. **LLM-генерация:** В модель (через OpenRouter в режиме `json_object`) отправляется промпт, требующий вернуть JSON со следующими полями:
   - `userTags` (2-5 видимых хэштегов)
   - `hiddenTags` (семантические концепции для поиска)
   - `relevance` (оценка важности от 0 до 1)
   - `resurfacingClass` (тип: "task", "idea", "reference", "archive")
   - `summary` (1-2 предложения, выжимка)
3. **Генерация Embeddings:** Текст разбивается на чанки по 800 символов, для каждого генерируется математический вектор (через функцию `getEmbedding`) и сохраняется в таблицу `note_embeddings`.
4. **Автоматическая маршрутизация (Folders):** Вектор поля `summary` сравнивается с описаниями папок пользователя (через RPC `match_folder` с порогом `0.82`). Если есть совпадение, заметка автоматически переносится в релевантную папку. В противном случае она падает в системную папку.

## 2. Чат-Агент (`/chat`)

Чат — это не просто окно для бесед, это полноценный Агент (Agentic AI), способный управлять рабочим пространством пользователя.

### Контекст (RAG)
Для генерации ответа Агент получает массивный системный промпт, в который встраиваются:
- Список папок пользователя (`{{FOLDERS}}`).
- Метаданные всех заметок пользователя (id, названия, теги) — `{{NOTES_LIST}}`.
- Контекст открытой в данный момент заметки (`{{ACTIVE_NOTE_CONTEXT}}`).
- Результаты векторного поиска (RAG) по локальной базе `pgvector`, если запрос пользователя пересекается с конкретными чанками (`{{RAG_CONTEXT}}`). Порог совпадения — `0.15`.
- История переписки.

### JSON Actions (Манипуляция данными)
Модель строго инструктирована возвращать ответ в формате JSON:
```json
{
  "answer": "Текст ответа пользователю...",
  "actions": [
    { "type": "createFolder", "folderName": "Проекты", "tempId": "123" }
  ]
}
```

**Доступные Actions (Действия):**
Агент может выполнять более 15 типов действий, включая:
- `createFolder`, `renameFolder`, `deleteFolder`, `mergeFolders`
- `createNote`, `updateNote`, `renameNote`, `trashNotes`
- `moveNotesToFolder`, `addTagsToNotes`
- `createStructuredIdeaNote` — специальный экшен для преобразования сырой мысли пользователя (из чата) в структурированную заметку с summary, keyIdeas и nextSteps.

### Безопасность и подтверждения
Для деструктивных действий (например, массовое слияние заметок `mergeNotes` или удаление) Агент проинструктирован сначала предлагать план в поле `answer` и возвращать пустой массив `actions`. Если пользователь соглашается ("да", "делай"), агент генерирует реальные действия.
