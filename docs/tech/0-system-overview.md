# Общая архитектура системы (System Overview)

SmartNotes AI — это распределенное веб-приложение, состоящее из клиентской части (PWA), сервера рендеринга и API, а также микросервисного бэкенда для работы с искусственным интеллектом.

## 1. Репозиторий и сервисы

Проект разбит на две основные части:

1. **SmartNotes-web**
   - Фронтенд и основной API-шлюз.
   - **Стек:** Next.js 16 (App Router), React, TypeScript, Tailwind CSS, Zustand, React Query.
   - **Сборка:** Turbopack/Webpack.
   - **Особенности:** Используется архитектура FSDDD (Feature-Sliced Design + Domain-Driven Design). Код поделен на `app`, `entities`, `features`, `services`, `shared`.

2. **backend**
   - Микросервис для тяжелых вычислений, интеграции с LLM и векторных операций.
   - **Стек:** Node.js, Fastify.
   - **Ключевые эндпоинты:**
     - `/analyze` — фоновый парсинг заметок, генерация эмбеддингов, авто-тегирование.
     - `/chat` — мощный AI-агент, способный анализировать контекст, отвечать на вопросы и управлять структурой папок.

3. **Supabase (Backend-as-a-Service) & Edge Functions**
   - Выступает в роли основной базы данных (PostgreSQL) и слоя аутентификации.
   - Расширение `pgvector` для хранения векторов и семантического поиска.
   - Supabase Realtime (Channels) используется как транспортный слой для совместного редактирования (CRDT/Yjs).
   - **Edge Functions (`analyze-note`, `embed`):** Альтернативный серверлесс-путь выполнения ИИ-задач.
   - **Полезные ссылки для разработки:** 
     - [Панель управления Supabase](https://supabase.com/dashboard/project/ammpwqfcutlyrjcarubc)
     - [Проект на Vercel](https://vercel.com/topmobs-projects/smartnotes-ai)
     - [Панель управления Railway](https://railway.com/project/009825d3-e65b-4c35-acf7-c57fcc8fc6ee)

> [!NOTE]
> **Двойной пайплайн выполнения ИИ-задач:**
> Если в окружении задана переменная `NEXT_PUBLIC_RAILWAY_GATEWAY_URL`, клиент отправляет запросы анализа и чата напрямую на выделенный Fastify-микросервис (`backend`). Если переменная отсутствует, приложение переключается на бессерверный режим (Next.js API Routes `/api/ai/*`), который делегирует задачи в Supabase Edge Functions. Оба пути идентичны по логике работы и поддерживаемым действиям.

## 2. Ключевые паттерны архитектуры

### Feature-Sliced Design (FSD)
Код во фронтенде жестко структурирован:
- **`shared`** — независимые утилиты (криптография, API-клиенты).
- **`entities`** — бизнес-модели (например, интерфейс Note, Folder).
- **`features`** — конкретные блоки функциональности (редактор, поиск, авторизация). Не могут импортировать друг друга напрямую.
- **`app`** — сборка всех слоев вместе (провайдеры, роутинг).

### Optimistic UI & Local First
Благодаря связке `Zustand` (локальный стор) и `React Query` (серверный кэш), интерфейс реагирует на действия мгновенно. Запросы к API уходят в фоне, а при возникновении ошибок состояние откатывается (Optimistic Updates).

### Offline-First и Синхронизация
Приложение спроектировано так, чтобы работать без интернета:
1. Заметки (CRDT-документы) сохраняются в IndexedDB браузера (`y-indexeddb`).
2. Медиафайлы (картинки) при отсутствии сети складываются в локальный кэш (Blob).
3. При появлении события `online` запускается фоновая очередь синхронизации.
