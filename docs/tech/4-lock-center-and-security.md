# Lock Center и Безопасность (Zero-Knowledge)

Модуль `features/lock-center` предоставляет функционал для криптографической защиты конкретных заметок ("Lock"), обеспечивая принцип **Zero-Knowledge**.

---

## 1. Zero-Knowledge Hashing (SHA-256)

Идея Zero-Knowledge заключается в том, что сервер не знает пароль пользователя и не может расшифровать или прочитать контент защищенной заметки.

В файле `lock-service.ts` реализована следующая логика:

### Установка пароля:
1. Пользователь вводит пароль для заметки на клиенте (браузер).
2. Генерируется уникальная строка `salt` (`crypto.randomUUID()`).
3. Пароль объединяется с солью и хэшируется через SHA-256: `hash = sha256(salt + password)`.
4. В базу (в объект `NoteLock`) улетает только `hash`, `salt` и флаг `hidden: true`. 
5. Сам пароль (plain text) **никогда не покидает браузер**.

### Снятие блокировки (Unlock):
1. Для просмотра заметки пользователь вводит пароль.
2. Браузер берет `salt` из базы, конкатенирует с введенным паролем и делает `sha256(salt + input)`.
3. Функция `secureCompare()` (защищенная от timing-атак) сравнивает полученный хэш с хэшем из базы.
4. Если они совпадают — контент открывается на клиенте.

## 2. Защита на уровне бизнес-логики

В базе данных Supabase контент остается "как есть" (мы не шифруем сам текст в БД, так как это сломает векторный поиск и совместное редактирование CRDT).
Защита реализована на уровне UI и бизнес-логики:
- **Сокрытие в списках:** Функция `maskLockedPreview(noteId)` заменяет текст превью заметки на "Защищенная заметка XXXXXX. Введите пароль для просмотра." во всех списках и виджетах.
- **Блокировка API-экспорта:** Сервисы экспорта (PDF, Markdown) и печати (`Print Service`) принудительно обрывают работу, если заметка заблокирована, а валидный пароль не передан.
- **Защита от AI:** Заблокированные заметки пропускаются векторным поиском (принудительно игнорируются при генерации контекста для Chat Agent).
