# Архитектура и Технический стек

SmartNotes AI — это не просто фронтенд с базой данных. Это сложная распределенная система, которая решает задачи оффлайн-доступности, совместного редактирования, интеграции сторонних хранилищ и машинного обучения.

---

## 🏗 Общая архитектура

Проект построен по принципам современного **Jamstack** и **Serverless** архитектуры:

- **Next.js 16 (App Router):** Выступает как единый оркестратор. Он отдает серверно-рендеренный (SSR) React, обрабатывает API-роуты (особенно для AI) и работает как безопасный прокси для загрузки файлов.
- **Supabase (Backend-as-a-Service):** Сердце проекта. Предоставляет PostgreSQL, авторизацию, Realtime WebSockets для сокетов и векторную базу данных `pgvector`.
- **Zustand + TanStack React Query:** Управление состоянием на клиенте. Zustand для локального UI (например, открыта ли боковая панель), а React Query для кэширования серверных данных.

---

## 🧠 AI Pipeline (ИИ под капотом)

Интеграция ИИ реализована как асинхронный фоновый пайплайн, запускаемый HTTP-запросом от клиента:

1. **Триггер:** После изменения заголовка или контента заметки клиент вычисляет локальный хеш и отправляет запрос на `/analyze` (на бэкенд-шлюз).
2. **Инициализация:** Бэкенд обновляет статус заметки в БД (`ai_status = 'pending'`) и моментально возвращает клиенту ответ `{ status: "queued" }`. Это гарантирует отсутствие задержек на UI.
3. **Фоновое выполнение:** Реальный анализ запускается в фоне:
   - В микросервисе **Fastify** это происходит через асинхронную функцию (IIFE), которая работает параллельно основному потоку.
   - В бессерверной среде **Next.js** запрос перенаправляется в Supabase Edge Function `analyze-note`, которая использует конструкцию `EdgeRuntime.waitUntil(...)` для продолжения работы после завершения HTTP-сессии.
4. **Анализ и LLM:**
   - Из контента удаляются HTML-теги и лишние пробелы.
   - Вызывается API **OpenRouter** (в режиме JSON) для получения краткой выжимки (`summary`), скрытых семантических тегов (`hiddenTags`), видимых тегов (`userTags`), рейтинга важности (`relevance`) и класса всплытия (`resurfacingClass`).
5. **Векторизация и Поиск:**
   - Текст режется на чанки по 800 символов, для каждого генерируется эмбеддинг через локальную модель (в Edge Function используется встроенная `gte-small` от Hugging Face через `Supabase.ai.Session`).
   - Векторы сохраняются в таблицу `note_embeddings` (расширение `pgvector`).
6. **Авто-маршрутизация:** На основе вектора выжимки вызывается RPC-функция `match_folder` (порог сходства `0.82`). Если найдена папка с подходящим семантическим описанием, заметка автоматически переносится туда.
7. **Оптимизация хэша:** При повторном сохранении вычисляется SHA-256 хеш нормализованного текста заметки. Если он совпадает с сохраненным в `metadata.content_hash`, повторный вызов к LLM блокируется, экономя трафик и токены.

## 🤝 Совместное редактирование (CRDT)

Чтобы пользователи могли писать текст одновременно без конфликтов (как в Google Docs), мы отказались от обычного сохранения всего текста и перешли на **CRDT** (Conflict-free Replicated Data Type).

1. **Редактор:** Tiptap (headless rich-text редактор).
2. **Алгоритм:** Yjs. Он разбивает текст на мельчайшие операции (добавил букву, удалил пробел).
3. **Синхронизация:** Изменения передаются по WebSockets через `Supabase Channels`. Даже если два пользователя одновременно изменят одно слово, Yjs математически верно сольет эти правки, не потеряв ни один символ.
4. **Оффлайн-сохранение:** Все Yjs-документы локально дублируются в `IndexedDB` (`y-indexeddb`). Если сеть пропадет, вы продолжите писать, а при появлении связи изменения мгновенно улетят коллегам.

## 📂 BYOS (Bring Your Own Storage)

Вместо того чтобы хранить картинки пользователей в нашем дорогом S3-хранилище, мы реализовали паттерн BYOS:

1. Пользователь логинится через Google OAuth и дает доступ к своему Google Drive.
2. При вставке картинки в редактор, файл не летит в Supabase.
3. Next.js API (`/api/media`) выступает как прокси, который сжимает картинку на лету и загружает напрямую на личный Google Drive пользователя.
4. В базе SmartNotes остается лишь легкий JSON объект (`MediaDescriptor`), содержащий ссылку (`URL`) на Google Drive.

Также реализован **Background Media Sync**: если вы писали заметку оффлайн и вставили картинку, она сохранится в локальную базу. Как только появится интернет, специальный фоновый воркер сам загрузит её в облако и обновит ссылки в тексте.

## 🔒 Lock Center (Zero-Knowledge)

Система защиты приватных заметок построена так, чтобы даже администратор базы данных не мог прочитать ваш текст.

- Пароль никогда не передается на сервер в открытом или зашифрованном виде.
- На клиенте (в браузере) из пароля генерируется SHA-256 ключ.
- Контент заметки скрыт. Экспорт или печать (Print Service) таких заметок заблокированы на уровне бизнес-логики приложения до тех пор, пока ключ не будет успешно валидирован на клиенте.
