SMARTNOTES 2026

Рабочая структура нового проекта. Это не карта старого кода, а опорная спецификация для переписывания системы с нуля под новый стек.

1. СТЕК

- Framework: Next.js 16 (App Router)
- Language: TypeScript (Strict Mode)
- Database: Supabase (Postgres + pgvector)
- Realtime: Supabase Channels + Yjs (CRDT)
- State: Zustand + TanStack Query
- UI: Tailwind CSS + shadcn/ui + Framer Motion
- Editor: Tiptap + Canvas API
- Media: Google Drive (BYOS) через Next.js Proxy
- AI: OpenRouter (LLM) + pgvector (Embeddings)
- Deployment: Vercel + PWA

2. АРХИТЕКТУРА `/src`

- `/app`
  - роутинг, layout, server actions, page composition
  - минимум бизнес-логики
- `/features`
  - `/notes`: CRUD заметок, статусы, напоминания, архив, корзина
  - `/editor`: Tiptap, страницы, canvas, math resolver, paste sanitize
  - `/folders`: CRUD папок, скрытие, сортировка, перемещение
  - `/ai-engine`: анализ, векторизация, hidden tags, relevance, folder suggestion
  - `/media-byos`: Google Drive proxy, upload flow, client-side compression
  - `/lock-center`: пароли, masking, блокировки защищенного контента
- `/entities`
  - модели и типы: `Note`, `Folder`, `User`, `AiMetadata`
- `/shared`
  - `/ui`: базовые UI-компоненты
  - `/api`: клиенты Supabase, Google, OpenRouter
  - `/hooks`: общие хуки
  - `/store`: глобальные Zustand-store
  - `/lib`: утилиты, валидаторы, crypto, search helpers
- `/services`
  - фоновые процессы: sync, reminders, notifications, ai queue, logging

3. БАЗОВЫЕ ПРИНЦИПЫ ПРОДУКТА

- Главная идея: "Создал и забыл".
- Система должна сама помогать находить, ранжировать, перекладывать и актуализировать заметки.
- Новая реализация не должна повторять старую архитектуру один в один.
- `SmartNotes_Features.txt` использовать как источник старых возможностей, но переписывать их заново под этот стек и эту структуру.

4. КЛЮЧЕВЫЕ СИСТЕМЫ

4.1. Notes Core

- Полный жизненный цикл заметок: create, read, update, trash, restore, delete.
- Многостраничная заметка: страницы, page titles, page drawings.
- Статусы и атрибуты: `pinned`, `isArchived`, `reminderAt`, `folderId`.
- Автосохранение через debounce и безопасные partial updates.

4.2. Editor Engine

- Tiptap как основа редактора.
- Поддержка базового форматирования, ссылок, списков, выравнивания.
- Canvas-слой поверх текста для рисунков.
- Math Resolver как отдельный модуль редактора.
- Санитизация вставки из буфера.
- Плагины редактора должны быть модульными и отключаемыми через feature flags.

4.3. Folders

- CRUD папок.
- Поля папки: имя, описание, `isHidden`, `folderOrder`.
- Ручная сортировка и перемещение.
- Папки участвуют в AI-классификации и поиске.

4.4. AI Engine / BrainEngine

- AI работает как pipeline, а не как одиночный вызов.
- После изменения заметки она получает `aiStatus = pending` и ставится в очередь анализа.
- Pipeline должен:
  - извлекать текст и структурированные данные заметки
  - при необходимости учитывать page drawings и vision-описания
  - генерировать `userTags` и `hiddenTags`
  - предлагать `folderId`
  - считать `relevance`
  - назначать `resurfacingClass`
- Поиск должен быть гибридным: full-text + semantic/vector search.
- Ручное перемещение заметки пользователем считать сигналом для feedback loop.

4.5. Offline / Sync

- Offline-first через IndexedDB.
- Локальная очередь `sync_queue` для изменений без сети.
- При восстановлении соединения изменения уходят в Supabase.
- Realtime обновления между устройствами через Supabase Channels.
- Для тяжелых локальных данных использовать SafeStorage fallback.

4.6. Security / Privacy

- Lock Center для защищенных заметок.
- Zero-knowledge подход: проверка пароля на клиенте, SHA-256.
- Контент заблокированных заметок маскируется до успешной проверки.
- Для защищенных заметок запрещены экспорт и печать.
- Служебные поля защищаются anti-autofill политикой.

4.7. Media / BYOS

- Пользовательские файлы хранятся на Google Drive пользователя, не в storage проекта.
- В заметках хранятся только ссылочные артефакты: `fileId`, URL, descriptor.
- Загрузка идет через Next.js proxy-слой.
- Изображения сжимаются на клиенте до 1920px, JPEG 0.8.
- При деградации Google Drive текстовая часть приложения должна продолжать работать.
- Локальные thumbnails можно кэшировать в IndexedDB.

5. ИНФРАСТРУКТУРА И УСТОЙЧИВОСТЬ

- Использовать кастомный домен для стабильной работы из РФ.
- OpenRouter выступает единым входом к LLM/API нейросетей.
- PWA обязателен: installable app, offline shell, системные уведомления.
- На старте нужен watchdog таймер около 8 секунд.
- Нужен `ConsoleLogStore` для диагностики, но сбор техданных только при явном feedback от пользователя.
- Все чувствительные или тяжелые данные в логах должны санитизироваться.
- Частичные обновления обязательны: фронтенд отправляет только дельту измененных полей.

6. ПРОИЗВОДИТЕЛЬНОСТЬ

- Для длинных списков использовать виртуализацию через `@tanstack/react-virtual`.
- Пагинация должна быть гибридной: серверная + клиентский `displayLimit`.
- Тяжелые задачи рендера и постобработки выносить в `requestIdleCallback` или отложенные процессы.
- Медиа, canvas и математические блоки не должны тормозить основной ввод в редакторе.

7. DATA MODEL MINIMUM

7.1. `notes`

- базовые поля заметки
- `isArchived`
- `pinned`
- `reminderAt`
- `lock_hash`
- `pages_count`

7.2. `folders`

- базовые поля папки
- `isHidden`
- `folderOrder`
- `access_role`

7.3. `ai_metadata`

- `promptVersion`
- `aiError`
- `relevance_decay_rate`

8. ПРАВИЛО ДЛЯ РАЗРАБОТКИ

- `SmartNotes_Structure.txt` определяет новый фундамент.
- `SmartNotes_Features.txt` нужен как архив старых функций и UX-идей.
- При генерации нового кода опираться сначала на этот файл, а затем уже переносить нужные возможности из старой карты в адаптированном виде.
